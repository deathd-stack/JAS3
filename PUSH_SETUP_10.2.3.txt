JAGOS 10.2.3 착륙 푸시 설정

1. GitHub deathd-stack/JAS3의 기존 index.html을 먼저 백업합니다.
2. 이 ZIP의 index.html, firebase-messaging-sw.js, manifest.webmanifest,
   jagos-push-icon.svg를 같은 배포 폴더에 업로드합니다.
   기존 manifest를 사용 중이면 먼저 백업하고 start_url/scope 설정을 확인하세요.
3. GitHub Pages 배포 후 홈 화면 JAGOS를 다시 열어 10.2.3인지 확인합니다.
4. 로그인하고 메인 조를 저장한 뒤 설정 > 착륙 알림 켜기를 누르고 허용합니다.
5. '등록 완료 · 메인 ... · 오늘 인바운드 ...편' 표시를 확인합니다.
   0편이면 당일 해당 조의 인바운드 메모가 등록되어 있는지 확인합니다.
6. 테스트 알림을 누릅니다. 발송 실패 메시지가 뜨면 그 메시지를 캡처합니다.
   테스트는 즉시 발송입니다. 이 테스트 성공만으로 앱 종료 상태 수신까지 검증된 것은 아닙니다.
7. 자동 착륙 확인은 Cloudflare jagos-api의 Cron Trigger가 필요합니다.
   설정 > 트리거 이벤트 > Cron Trigger에 * * * * * (매 1분)가 있는지 확인합니다.
   코드 파일에 scheduled 함수가 있어도 Cron을 설정하지 않으면 자동 실행되지 않습니다.
8. Worker의 기존 JAGOS_PUSH KV 바인딩과 INCHEON_API_KEY,
   FCM_CLIENT_EMAIL, FCM_PRIVATE_KEY Secrets를 유지합니다.
   Secrets 값은 다른 사람에게 보내지 마세요. 푸시 테스트 실패 시 설정 존재 여부만 확인합니다.

알림 감시는 기기에서 마지막으로 등록한 '오늘 메인 조 인바운드 메모' 기준입니다.
매일 근무 시작 시 앱을 한 번 열어 등록 상태와 편수를 확인하세요.
앱을 닫은 뒤 새로 배정된 편은 다음 앱 실행 전까지 기기에 등록되지 않을 수 있습니다.
현재 구성은 API 갱신·매 1분 서버 확인·푸시 전달에 따른 지연이 있을 수 있습니다.
정확한 착륙 순간을 보장하거나 업무상의 공식 운항 확인을 대체하지 않습니다.
소리는 OS 기본 알림음이며 무음/집중모드/알림 설정/절전 정책에 따라 안 울릴 수 있습니다.
아이폰은 홈 화면에 추가된 앱으로 실행해야 합니다. 홈 화면 앱이 아닌 브라우저에서
열었다면 지원 오류가 날 수 있습니다. 기존 앱 아이콘을 먼저 삭제하지 마세요.

이 파일들은 로컬 문법 및 모의 동작 검증만 완료했습니다.
실제 배포, 기기 등록, 앱 종료 상태 알림/소리 수신은 사용자 기기에서 확인해야 합니다.
이번 패치는 알림 메뉴·상태 표시·FCM 서비스워커 보존과 설치 메타정보만 변경합니다.
LDM 계산, 운항 조회, 스케줄 데이터는 변경하지 않았습니다.
